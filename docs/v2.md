## Decisões por fase

- **F9**: importância = fórmula determinística (base=max(explícita,confiança)
  × decaimento anual + boost de acesso + boost projeto). Working memory é
  tabela com `expires_at`; leitura após expiração deleta.
- **F10**: reusa router/context-builder; memórias entram rankeadas;
  tools/skills como placeholders até F12/13.
- **F11**: permissão mínima `context`; agente paused/inativo bloqueado.
- **F12**: seed automático das 10 tools MCP quando catálogo vazio
  (`seedIfEmpty` no servidor).
- **F13**: NÃO reconstruímos o mecanismo de skills do OpenCode — o Brain só
  DISCOVER/RESOLVE/RECOMMEND. Provenance obrigatória: source/repo/path/hash.
  task-observer tratado como fonte externa, não modificado.
- **F14**: patternKey explícito recomendado para agrupar correções
  semanticamente iguais; aceitação não aplica nada crítico automaticamente.
- **F15**: pesquisa web real fica para depois (requer fetch externo +
  extração); o engine cobre ingestão/normalização/conflito/citação local.
  Jaccard ≥0.85 sobre tokens normalizados (len>2) dos DOIS lados.
- **F16**: projetos são entities type=project; intelligence = agregação
  determinística, sem dados inventados.
- **F17**: unifiedQuery orquestra tudo em uma chamada e registra
  `unified.query` em events (observabilidade).

## Limitações conhecidas

1. Pesquisa web autônoma (F15) requer integração de fetch+extração futura.
2. Importância não aprende pesos — fórmula fixa configurável via código.
3. Skills: ranking lexical simples (sem embeddings); budget default 3/3.
4. Agentes: sem execução de tasks — apenas resolução de contexto/permissões.
